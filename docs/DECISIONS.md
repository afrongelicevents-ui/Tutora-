You asked me to make sensible choices instead of stopping to ask. Each one is listed here so you can change it later. "Tutor can change" means it's a setting in the tutor's admin area, so no code change is needed.

## Claiming the tutor account

| #   | Decision                                                                                                                                                                                                                                                                                        | Why                                                                                                    |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| D4  | At first deploy, the tutor's email is set once as the secret `TUTOR_EMAIL`. The tutor opens **`/setup`** and types that email. ## Money

## Lesson room

| #   | Decision                                                                                                                                                                                                                                                                                                    | Why                                       |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| D20 | **The call goes directly between phones** (WebRTC). The two phones find each other by exchanging a few setup messages through the database, which costs a few requests a minute. A dedicated always-on room server ("Durable Object") would need a second Cloudflare app, and so a more complicated deploy. | Simple deploy, $0. Can be upgraded later. |
| D21 | **Audio only by default**, capped at about 24 kbps (roughly 11–20 MB per hour). Video is a button and is capped at 360p and about 300 kbps. Screen share is also a button. The whiteboard, chat and file messages travel inside the call, so they don't touch the server.                                   | Brief: low data.                          |
| D22 | **If a direct connection fails** (some mobile networks block it), the call can be relayed through Cloudflare's TURN service, but only once a TURN key is added (optional, free tier). Without it, most calls still connect directly.                                                                        | Avoids another account on day 1.          |
| D23 | **Group calls connect every phone to every other phone** (fine for up to about 4 people). A Cloudflare SFU can replace this later for bigger groups.                                                                                                                                                        | Simple.                                   |

## Added for the first launch (no email service needed)

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                     | Why                                                                                           |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| D37 | **The site runs without an email service.** Accounts work straight away (no confirmation email). Forgotten passwords: the student asks the tutor, who makes a temporary password on the student's page. Emails switch on by adding `RESEND_API_KEY` and `EMAIL_FROM` in Cloudflare later.                                                                                                    | Launch with only Cloudflare + Neon; fewer accounts and secrets.                               |
| D38 | **The tutor claims the site at `/setup` with a one-time setup code.** The deploy workflow makes the code (valid 14 days) and stores only its SHA-256 fingerprint; the public log shows it only encrypted with a key held by whoever deploys. The code is deleted once used, and the database allows only one tutor, so `/setup` closes for good. The link `/setup?code=…` fills the code in. | Nobody else can grab the tutor account before the owner, with no extra step for the owner.    |
| D39 | **Uploaded files are stored in the database** when no R2 bucket is connected (binding `FILES`).                                                                                                                                                                                                                                                                                              | No card needed to switch on R2; files are small (photos are shrunk on the phone, 5 MB limit). |
| D40 | **The login secret is derived from `DATABASE_URL`** by the deploy workflow if `BETTER_AUTH_SECRET` isn't set. Changing the database password logs everyone out once.                                                                                                                                                                                                                         | One secret fewer to create by hand.                                                           |
| D41 | **Email and password changes happen in Settings → Account.** Without email, changing the login email asks for the current password instead of sending a link.                                                                                                                                                                                                                                | The owner manages their own details in the admin area.                                        |
| D42 | **Deploying needs only two keys:** a Neon API key and a Cloudflare API token, saved as GitHub secrets. The deploy workflow finds (or creates) the database, can reset its password, finds the Cloudflare account, creates the free `workers.dev` address, sets the app's secrets and deploys. Nothing secret is printed in the (public) logs.                                                | Fewest steps for a person on a phone; secrets never pass through chat.                        |

## Many tutors on one platform (Tutora for other tutors)

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Why                                                                                       |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| D43 | **Every tutor's data is separate.** Each tutor has a profile (`tutor_profile`) and every table that belongs to a tutor has a `tutor_id`. Every server query uses the logged-in tutor's id, so another tutor's students, lessons, money, homework, reviews and settings are simply "not found". Tested in `tenancy.db.test.ts`.                                                                                                                                                  | Tutors and students can never see another tutor's data, even if a link is guessed.        |
| D44 | **Students are linked to a tutor (`enrollment`) once the tutor accepts a lesson** (or the student buys one of the tutor's packages). A request alone links nothing, so strangers can't see a tutor's payment details. A student can have several tutors; their area shows lessons, payments and homework with each tutor's name. A tutor only sees students linked to them.                                                                                                     | One login per student, many tutors possible, payment details only for real students.      |
| D45 | **Tutor pages live at `/t/<address>`**, made from the tutor's name (`/t/chipo-moyo`). Only approved tutors have a public page. The WhatsApp button and footer number on a tutor page are that tutor's own number from their Settings; Tutora's own pages show no number.                                                                                                                                                                                                        | Each tutor gets their own page; no one tutor's number on the whole site.                  |
| D46 | **New tutors join through `/join`** and wait for the platform owner's approval ("pending"). They can log in and switch on the authenticator app meanwhile; the tutor area opens once approved, starting with the setup wizard. The owner can also add a tutor directly (approved, with a temporary password shown once).                                                                                                                                                        | Only tutors the owner trusts can take bookings and payments.                              |
| D47 | **Platform owner role (`owner`)** with its own area `/owner`: see all tutors, approve, suspend, make active again, add tutors. Suspending hides the tutor's page, stops new bookings and logs them out. The owner needs the authenticator app like tutors.                                                                                                                                                                                                                      | You manage who teaches on Tutora.                                                         |
| D48 | **The owner account is made at `/setup` with a one-time code from the deploy** (same safe method as before; it now creates the owner, not a tutor). `/setup` without a code goes to the homepage; it is linked from nowhere and closes once the owner exists.                                                                                                                                                                                                                   | Nobody can grab the owner account; `/setup` is never a landing page.                      |
| D49 | **Ready for tutor billing later, not switched on:** each tutor has `plan` (now "free") and `plan_until`.                                                                                                                                                                                                                                                                                                                                                                        | No billing yet, but no database change needed when it comes.                              |
| D50 | **One login for everyone**, then each person lands in their own area: owner admin, tutor dashboard (or "waiting for approval"), or the student area. "Stay logged in on this phone" is ticked by default (30 days); untick it and the login ends when the browser closes. Log out is in the menu.                                                                                                                                                                               | Simple on shared phones.                                                                  |
| D51 | **Visitors never see admin links.** The menu only shows what each role may open. Opening a page you may not see shows a friendly page ("Please log in" or "This page is for tutors only") instead of a bare error; page-data requests get a plain 403.                                                                                                                                                                                                                          | Cleaner and safer.                                                                        |
| D52 | **Only the Tutora admin can make a temporary password** for a student or parent who forgot theirs (no email service yet). The student must choose their own new password at the next login, and everyone can change their password in Account. Tutors can't reset students' passwords.                                                                                                                                                                                          | A tutor must never be able to log in as a student (they could see other tutors' lessons). |
| D53 | **Receipt numbers are counted per tutor** (each tutor starts at R-000001).                                                                                                                                                                                                                                                                                                                                                                                                      | Tutors can't guess how busy other tutors are.                                             |
| D54 | **The existing tutor (your dad) keeps everything**: the migration moves his settings, students, lessons and money to his own profile and page (`/t/<his-name>`), approved.                                                                                                                                                                                                                                                                                                      | Nothing lost.                                                                             |
| D55 | **Separate TEST site** (`tutora-test`, its own Cloudflare Worker and its own Neon database branch "test" with its own password; the live database is never touched). It shows a "TEST SITE — fake data" bar, skips the authenticator step so shared test logins work, and the owner has a "Reset test data" button. It is filled with fake tutors, students, parents, lessons, requests, payments in every state, receipts, packages, homework and reviews on the first deploy. | Try everything without touching real people's data.                                       |
| D56 | **The test logins' shared password is made during the deploy** (never written in the public code) and shown in the public logs only encrypted, like the owner setup code.                                                                                                                                                                                                                                                                                                       | The repository is public.                                                                 |
| D57 | **Lesson-room chat is not saved** (it goes directly between the phones), so the test data has no chat history. Everything else in the room can be tried on the test site with two phones.                                                                                                                                                                                                                                                                                       | Privacy and low data.                                                                     |
| D58 | **Logins are checked against the database on every request** (no 5-minute login cache).                                                                                                                                                                                                                                                                                                                                                                                         | A logout, suspension or password reset takes effect at once.                              |
| D59 | **The test database is wiped and filled with fake data before the test website goes live**, and again whenever it holds anything that isn't our fake data (e.g. if Neon could only make a full copy).                                                                                                                                                                                                                                                                           | Real people's data can never appear on the test site.                                     |
| D60 | **Anyone given a temporary password by someone else (students reset by the admin, tutors added by the admin) must choose their own at the next login.** The student also gets an email about the reset when email is switched on.                                                                                                                                                                                                                                               | Nobody keeps knowing another person's password.                                           |
| D61 | **Tutors who join themselves have an unconfirmed email** until they confirm it (when email is on); the admin sees "check the email" before approving.                                                                                                                                                                                                                                                                                                                           | Stops someone signing up with another teacher's address unnoticed.                        |
